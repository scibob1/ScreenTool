# 隐私保护设计（1.5.0）

目标：在**单个 App** 内做一个“按需选择强度、可自由组合、但组合有约束”的个人隐私保护方案。接受无法完全保护的可能：普通个人方案仍允许用户通过系统操作停止或卸载应用，不宣传整机不可退出。

## 1. 状态与角色

| 对象 | 说明 |
|---|---|
| `Protect`（统一保护控制器） | 唯一的判断来源。持有上锁状态 `locked`（持久化到 `pv_locked`，用 commit 立即落盘）和验证会话 `session`。 |
| 上锁 | 幕布全屏盖住，解除必须验证。重启/被杀后恢复仍是上锁。 |
| 验证会话 | 验证通过后一段时间内不用再验证（有效期 0 = 只在本应用保持打开期间有效）。任何上锁动作立即让它作废。 |
| 紧急释放 | 长按上锁的幕布 N 秒：只撤遮罩，**不授予会话**，不触发清理。 |

## 2. 操作与是否需要验证（`Protect.needVerify`）

| 操作 `Purpose` | 入口 | 何时需要验证 |
|---|---|---|
| UNLOCK 解除遮罩 | 点幕布、返回键、通知“展开”、快捷方式切换形态 | 上锁时**每次**都要（不看会话） |
| STOP 停止服务 | 通知“停止”、磁贴、快捷方式、设置页关闭 | 上锁时每次都要 |
| SETTINGS 打开设置 | 主页滑动、设置各页 | 保护开启 + 会话没有授权“设置”范围（且该页面自己还没验证过） |
| BACKUP 备份/恢复 | 备份页、导出、恢复 | 保护开启 + 会话没有授权“备份”范围 |
| POLICY 修改保护策略 | 隐私保护页、清除全部数据 | 保护开启 + 会话没有授权“保护策略”范围（默认不授权，每次都问） |
| RESET 恢复默认 | 设置 → 通用 | 同 SETTINGS；且**不会改动**任何隐私配置 |
| TEST 自检 | 保护自检 | 只试验流程，不授予任何东西 |

不经过验证、也不改变上锁状态的事件：护眼休息结束/跳过、低电量、定时关闭常亮（上锁时只停常亮，服务和遮罩保留）、双击主页退出（但会触发“离开应用”）。

授权范围的含义：保护开启后设置/备份/保护策略一律要验证；`pv_sc_settings` / `pv_sc_backup` / `pv_sc_policy` 决定“一次验证成功后顺带放行哪些范围”。开=有效期内不再追问；关=每次进入都重新验证（只有刚为它验证过的页面本身可继续使用，用 `Protect.epoch` 代数判断：上锁、离开应用、有效期结束都会让代数 +1，旧页面的“已验证”随之失效）。

## 3. 验证流程

- 只验证自定义密码：验证悬浮窗直接画在幕布之上（`VerifyOverlay`）。
- 涉及系统锁屏凭据：由 `VerifyActivity` 承载。服务**先趁遮罩还在**把页面拉起（应用此时仍算有可见窗口，后台启动页面不会被拒），页面出现后通知服务**撤掉自己的所有悬浮窗并暂停自动重挂载**，避免挡住系统输入界面；结束后恢复。3.5 秒内没打开页面就保持锁定并说明原因；验证页 90 秒没回报，服务自己恢复遮罩。
- 验证方式不可用（没设密码 / 设备没有锁屏 / 系统验证无法启动）：**不降级**，页面只显示原因，有恢复码时可用恢复码重置（重置会关闭保护总开关）。
- 系统验证通过后若还需要密码，60 秒内完成。

## 4. 设置组合的约束（`Protect.check`）

见 README“组合是有约束的”一节。核心：任何不允许的组合都是**拒绝 + 说明**，不会静默改成别的；运行中前提失效（系统验证、增强覆盖）同样不静默降级。

## 5. 失败响应与清理顺序（`FailPolicy` / `AuthCleaner`）

1. 输错密码/恢复码 → 内置冷却阶梯；达到阈值后按选项执行：逐步加长冷却 / 清除授权文件 / 清除软件数据。
2. 清除授权文件：后台线程，逐层（用各自的文档 ID）删除，再重新读取确认已空，最多 3 轮；权限失效或读取失败 = 失败；系统允许时把文件夹本身也删除。
3. 清除软件数据：**只在第 2 步确认成功后**执行；否则数据保留、保持锁定，记 `pv_wipe_pending`，下次失败/启动时自动重试。

## 6. 没有通知时

遮罩、验证页、自动上锁、紧急释放都不依赖通知；只有通知按钮不可用。`Caps` 逐项检测并在“保护自检”里展示，护眼休息的紧急退出在通知不可见时自动改成长按幕布。

## 7. 已知局限

- 无法防住：系统设置里清除/卸载应用、ADB、root、刷机；部分系统对悬浮窗 `FLAG_SECURE` 不生效。
- 部分系统（如鸿蒙）可能清理悬浮窗或限制后台启动页面；已做重挂载、看门狗和失败时保持锁定，但无法从应用侧完全保证。
- 熄屏震动依赖 CPU 唤醒锁，更耗电。
