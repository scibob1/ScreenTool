# 屏幕常亮 · Screen Keep-On

[English](README_EN.md) ｜ 包名 `com.wave.screentool` ｜ MIT 协议

很多应用需要长时间运行，但系统会自己熄屏，任务就被打断。这个应用让屏幕保持常亮，同时显示**纯黑、亮度可调到很低**的画面，做到省电、轻量，让其他应用能稳定地一直跑下去。

- 纯 Java，**没有任何第三方库**，界面全部用代码生成，APK 很小。
- **不联网**，没有统计、没有广告，**不申请存储权限**。
- 所有功能“用到才加载”：设置页、颜色选择器、图片管理等都是进入时才创建，退出即销毁；没有内容要刷新时不运行任何定时器。
- 同时适配安卓和鸿蒙（鸿蒙 4 及以前的安卓兼容环境；是否能运行安卓应用取决于设备）。

---

## 一、三种常亮方式

| 方式 | 说明 |
|---|---|
| **悬浮球** | 停靠在屏幕侧边的小球，可显示秒表；点按它打开幕布。 |
| **悬浮幕布** | 盖住屏幕的黑色遮罩（可全屏，也可自定义范围），可显示秒表和系统时间。 |
| **仅通知** | 不显示任何窗口，靠前台通知和唤醒锁保持常亮；通知里有系统绘制的秒表和调亮/调暗按钮。 |

球和幕布可以分别开启或关闭；两个都关闭时就是“仅通知”模式。

### 悬浮球与幕布的联动
- 点悬浮球 → 变成幕布；点幕布或按返回键 → 变回悬浮球。
- **操作窗口期**（默认 600 秒）：悬浮球停留这么久后自动变成幕布。设为 **0 = 防误触**：幕布不响应点按，只能用返回键切回悬浮球，悬浮球也不会自动展开。
- **幕布切回悬浮球时重置秒表**（默认开启）。
- **悬浮球贴边**（默认开启）：5 秒没有被触摸，就藏进屏幕边缘约四分之三并变淡；触摸一下弹出，再点一下才打开幕布，避免误触。
- 悬浮球可拖动，松手后自动吸附到左边或右边，位置会被记住。

### 悬浮球外观
- 形状：圆形 / 长方形；大小可调（默认 36dp）。
- 秒表显示风格：全部秒数 / 时:分:秒（按需显示）/ 自适应（前几分钟显示秒，之后只显示分钟，如 `6m`）。
- 文字变长时：球跟着变大，或球不变、文字缩小。

### 悬浮幕布
- 范围：输入数值（左/上/右/下百分比），或在全屏编辑器里用手指拖动边界。
- 显示内容：秒表（默认关）、系统时间（精确到秒，默认开）。
- 上下滑动或音量键调节亮度；亮度条在操作时短暂显示。
- 尽量盖住状态栏和导航栏：增强模式下窗口层级高于系统栏，可直接盖住；普通悬浮窗层级更低，只能请求系统隐藏系统栏（尽力而为）。

## 二、主页

全黑的全屏页面（默认显示系统时间），支持系统小窗和分屏（如华为小窗）：

| 手势 | 作用 |
|---|---|
| 上滑 / 下滑 | 调高 / 调低亮度 |
| 向左滑 | 打开设置 |
| 向右滑 | 开启屏幕常亮 |
| 双击 | 退出主页并移除任务卡片 |
| 返回键 | 隐藏应用（最近任务里保持黑色画面，不会闪白） |

设置页向右滑动即可返回；从最近任务回来时，如果上次停在设置页就直接回到设置页。

## 三、保持屏幕常亮的手段

- **窗口常亮标记**：悬浮窗带 `FLAG_KEEP_SCREEN_ON`，窗口显示着，系统就不会自动熄屏。
- **唤醒锁（WakeLock）**：不需要窗口。部分系统（如鸿蒙）会无视它，所以“无窗口”状态下默认还会放一个**看不见的 1 像素窗口**兜底。
- 在设置里可以分别选择：窗口标记 + 唤醒锁（推荐）/ 仅窗口标记 / 仅唤醒锁；无窗口时：自动 / 仅唤醒锁 / 仅隐形窗口。
- 可选“仅充电时保持常亮”（默认关闭）、低电量自动停止（默认 15%）、定时自动关闭。
- **熄屏后间歇震动提醒**（默认关闭，间隔默认 5 秒）：屏幕熄灭时提醒你，亮屏或关闭常亮后自动停止。

## 四、亮度

- 窗口亮度（无需权限）+ 系统亮度（需要“修改系统设置”权限）。有的系统（如鸿蒙）不理会窗口亮度，授权后会同时调节系统亮度，**停止时自动恢复原来的亮度和自动亮度开关**；如果进程被异常杀掉，下次打开应用会补恢复。
- 亮度曲线为平方曲线，低亮度区域更细腻。

## 五、护眼强制休息

- 每隔 N 分钟（默认 20）弹出全屏幕布，休息 M 秒（默认 60），休息期间**屏蔽所有触摸和按键**。
- 休息前 5 秒用短提示预告（可改或关闭）。
- 可单独选择“护眼休息风格”；风格里有护眼休息专用的背景（颜色或图片）和文字颜色。
- 紧急退出：通知栏的“跳过休息”按钮；如果关闭了通知栏按钮，则长按幕布 5 秒。
- 计时按真实时间计算，手机休眠醒来后会补算。

## 六、风格与背景图片

- 内置三种风格：纯黑 / 纯白 / 护眼黄。可新建自定义风格（重命名、长按拖动排序、删除）。
- 每个风格有 8 处颜色（都带透明度）：主页与设置页背景、悬浮球、幕布、系统时间文字、秒表文字、设置页文字、护眼休息背景、护眼休息文字。
- 颜色选择：色盘 + 明度条 + 透明度条 + `#AARRGGBB` 输入框 + 带棋盘格的大预览。
- **背景图片 / 幻灯片**：主页、幕布、护眼休息的背景颜色右边有“图片”按钮。
  - 可一次多选图片，组成**图片集**；多张图会按间隔幻灯片放映（默认 10 秒，可选顺序/随机、铺满裁剪/完整显示、渐变切换）。
  - 带**小窗预览**，图库里可以删除图片、重命名或删除图片集。
  - **只保存图片链接**，通过系统文件选择器获取长期访问权，不申请存储权限。个别系统不给长期授权时，会自动把该图复制一份到应用内，避免重启后失效。找不到的图片放映时自动跳过。

## 七、备份与恢复

- 通过系统文件选择器读写，文件名自动带时间：`ScreenTool_backup_2026-10-21_14_30_05.json / .zip`。
- **仅设置（.json）**：设置、风格、图片集（只含链接）。
- **含图片（.zip）**：额外把背景图片打包；恢复时同名图片直接覆盖，读不到的图片自动跳过。

## 八、稳定性与增强模式

- **稳定性向导**：权限状态、忽略电池优化、自启动与后台活动入口（华为/荣耀优先跳转，进不去时打开应用信息页）、锁定任务卡片提示、可选开机自启。
- **打开应用时自动启动**（默认启动悬浮常亮），也可改为仅通知或不启动。
- **悬浮窗自动恢复**：悬浮窗被系统移除（例如托管它的应用被清理、无障碍服务断开）后，会自动重新挂载，间隔从 0.8 秒逐步加大到最多 30 秒；亮屏和解锁时也会检查。
- **增强模式（可选，默认关闭）**：利用无障碍服务获得比普通悬浮窗更高的窗口层级，可改善对部分系统应用（如备忘录）的覆盖、盖住状态栏和导航栏，并避免系统弹出“正在其他应用上层显示”的提示；还能让系统更不容易清理本应用。**它不读取、不收集屏幕上的任何内容**，只监听本应用自己的窗口事件。

### 关于系统自动弹出的“正在其他应用上层显示内容”通知
这是 Android 系统在应用显示普通悬浮窗时自动加的，应用无法移除。长按该通知可关闭；使用增强模式或“仅通知”模式可避免。

## 九、快捷方式

- 桌面长按图标：悬浮球 / 幕布 / 仅通知 / 停止。
- 下拉快速设置磁贴（部分系统如鸿蒙不支持，不影响使用）。
- 通知栏按钮（可在设置里关闭）：切换球/幕布、重置计时、停止；仅通知模式下为调暗、调亮、停止；护眼休息时为跳过休息、停止。

## 十、资源与省电设计

- 悬浮球 / 幕布 / 隐形窗口 / 各设置页 / 图片管理页都是用到才创建，不用就销毁。
- 没有文字要显示时，**不运行任何每秒定时器**；自适应风格进入“只显示分钟”后，悬浮球每分钟才刷新一次；屏幕熄灭时暂停刷新和幻灯片。
- 通知里的秒表由系统绘制（Chronometer），应用本身不需要每秒唤醒。
- 当前风格只缓存颜色和图片集 id，主页和悬浮服务不解析完整风格列表；图片按目标尺寸缩小解码（RGB_565），用完立即回收。
- 中文对照表只在设置类页面存在时加载，主页和服务只用 16 条内置文字。
- 修改设置时，只有影响外观的设置变化才会重建悬浮窗。
- 拖动调亮度时，系统亮度只在数值变化时才写入。

## 十二、权限说明

| 权限 | 用途 |

| `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_SPECIAL_USE` | 用前台服务稳定地保持常亮 |
| `POST_NOTIFICATIONS` | 显示前台服务的通知（安卓 13+） |

## 十三、已知限制

- 部分系统应用（如备忘录）的窗口层级更高，可能盖住或拦截悬浮窗；可尝试增强模式，或长按幕布 5 秒。
- 在鸿蒙上，悬浮窗可能只显示在其他应用之上，回到桌面时看不到；托管它的应用被清理后悬浮窗也可能消失，应用会自动尝试恢复。这是系统对安卓悬浮窗的处理方式，应用无法完全改变。
- 普通悬浮窗无法盖住状态栏；增强模式可以。
- 鸿蒙 NEXT 及以后的原生系统不保证能运行安卓应用，是否可用取决于设备。
- 下拉快速设置磁贴在部分系统（如鸿蒙）不可用。
- 唤醒锁在部分系统上会被无视，所以默认配合隐形窗口使用。

## 十四、构建

推送到 GitHub 后，**Actions → Build APK** 会自动打包，在对应运行页面最下面的 **Artifacts** 下载 `ScreenTool-apk`。打标签（如 `v1.5.0`）并推送，会自动发布到 Releases。

本地构建：Android Studio 打开，或 `gradle assembleRelease`（JDK 17 + Android SDK 35，Gradle 8.9，AGP 8.7.3）。

> 命令行构建需要能定位到 Android SDK：要么在项目根目录建一个 `local.properties` 写入 `sdk.dir=/你的/Android/Sdk/路径`（Android Studio 打开项目时会自动生成），要么在环境变量里设 `ANDROID_HOME`（或 `ANDROID_SDK_ROOT`）指向 SDK 目录。这个文件已加入 `.gitignore`，不会随仓库分发。

> 仓库里带有一个**公开的签名密钥**（`app/screentool.keystore`），目的是让每次打包的 APK 都能直接覆盖安装升级。它只适合自用分发，请勿用来上架应用商店。

版本号写在 `app/build.gradle`（`versionCode` / `versionName`）。清单文件里不再写版本号。

工程是**单模块**（只有 `app`），可以直接用只支持单模块的本地编译器编译；早先的 `privacy-core`、`privacy-android`、`privacy-demo-host` 三个模块和 `app` 里的重复隐私代码已在 1.5.0 删除。

## 十六、隐私保护（仅保护本应用自己）

设置 → 隐私保护。**全部默认关闭**：升级不会把你现有的护眼、常亮设置自动变成密码锁；旧版本设置过的密码、恢复码、授权文件列表会保留，但总开关一律保持关闭，需要你自己重新打开。

它能做什么：给悬浮幕布加一个**全屏隐私遮罩**（上锁），并在本应用的设置页、备份、保护设置前加一道验证。它**只保护本应用**：不能锁其他应用；系统随时可以停止或卸载本应用，不宣传“整机不可退出”；也不可能做到万无一失。

### 五个维度，自由组合

| 维度 | 可选项 |
|---|---|
| 1 验证方式 | 自定义密码 / 系统锁屏凭据（PIN、图案、密码） / 两者都要（先系统，再密码） |
| 2 触发条件 | 手动（设置页按钮、通知“上锁”按钮、桌面“上锁幕布”快捷方式） / 展开幕布时（每次幕布弹出就上锁，关闭要验证） / 定时（启动或每次解锁后 N 分钟） / 熄屏后 / 离开本应用后 |
| 3 界面限制 | 点击不能关闭 / 返回键需要验证 / 防截屏录屏 / 增强覆盖（无障碍悬浮窗，盖住状态栏和导航栏） |
| 4 授权范围 | 保护开启后，设置、备份、保护策略一律要验证；“一次验证顺带放行哪些范围”可选：打开设置 / 备份与恢复 / 修改保护策略（开=有效期内不再追问；关=每次进入都重新验证，默认只有保护策略是关）。解除遮罩上锁期间每次都要验证。另有“验证有效期” |
| 5 失败响应 | 保持锁定（始终）/ 逐步加长冷却 / 清除授权文件和文件夹 / 清除软件数据 |

### 组合是有约束的，不是所有开关都能任意叠加

不允许的组合会**被拒绝并说明原因**，不会悄悄改成别的：

- 要用系统验证，设备必须先设置锁屏；**运行中系统验证变得不可用也不会悄悄降级**成只验证密码——保持锁定、明确告知原因，并保留紧急释放。
- 选“自定义密码”前必须先设置密码；保护开着时不能移除正在使用的密码。
- “点击不能关闭”会同时要求“返回键需要验证”（否则就没有解锁入口）。
- “增强覆盖”需要无障碍服务已连接；中途断开时会明确提示并改用普通悬浮窗，不假装仍在增强。
- 要开“清除授权文件”，必须已经添加并且读写权限都有效的授权项；要开任何清理，失败次数至少 3；移除最后一个授权项前必须先关掉它。
- 触发条件需要能显示遮罩（悬浮窗权限或增强模式）。

### 现有入口都统一经过保护控制器

上锁后（`Protect` 是唯一的判断来源）：

- 单击幕布 / 返回键：不再直接切回悬浮球，而是请求验证（或按“点击不能关闭”被忽略）。
- 护眼休息结束、跳过休息：只结束休息，**不解除隐私锁**，休息结束后回到上锁的遮罩。
- 低电量停止、定时关闭常亮：上锁时只停止常亮本身，服务和遮罩保留，**不会自动变成“验证通过”**。
- 通知“停止/展开”、快速设置磁贴、桌面快捷方式、设置页里的“关闭”：都要先验证。保护开启时通知按钮直接指向验证页，不经过后台跳转。
- 打开设置 / 备份 / 修改保护策略 / 恢复默认 / 清除全部数据：按授权范围验证；备份文件不包含也不会恢复任何保护配置，恢复默认也不会改动它们。
- 双击主页退出不需要验证，但会触发“离开应用”。
- 重启或被系统杀掉再恢复时，上锁状态会保留（落盘），重启后直接回到上锁的遮罩。
- **系统验证期间**：服务会撤掉自己的遮罩并暂停自动重新挂载，避免挡住系统输入界面；结束后自动恢复。

### 紧急释放

上锁后**长按幕布 N 秒**（默认 10，可设 5–60）撤掉遮罩；有独立开关“紧急释放”（默认开启）。验证当前用不了时不允许关掉它；关掉后上锁的遮罩只能靠验证移除。它不依赖通知，没有通知也可用；它只是移除遮罩，**不授予验证**，设置、备份、保护策略仍然需要验证；也不触发任何清理。

### 没有通知 / 没有通知权限

服务、遮罩、验证页、自动上锁触发条件、紧急释放都**不依赖通知**，没有权限或被系统屏蔽时照常运行，只是通知上的按钮（停止、展开、跳过休息、上锁）用不了；这时护眼休息的紧急退出自动变成长按幕布 5 秒。设置 → 隐私保护 → “保护自检”会逐项列出现在哪些能运行，并可实测遮罩窗口和验证页。

### 验证失败之后

- 密码只存加盐哈希（PBKDF2-SHA256，迭代 15 万次；旧版本的哈希仍可验证），从不存明文；连续输错有内置的冷却阶梯，重启后冷却不会被清零。
- 清除授权文件/文件夹：在后台线程逐层删除，**逐项重新读取确认已清空**，最多重试 3 轮；权限失效、读取失败都算失败，不会被当作成功。
- 清除软件数据：**只有授权文件全部确认删除成功之后**才会执行（清除数据会撤销文件授权，必须先删文件）。文件没删干净时数据保留、应用保持锁定，并记下“未完成”，之后自动重试。
- 一次性恢复码：生成时只显示一次，只保存哈希；用恢复码会作废恢复码和密码，并**关闭保护总开关**，由你重新设置。
- 密码、哈希、恢复码在独立文件里，**永不进入备份**。

### 验证页

固定深色底白字，不使用自定义风格或背景图；开启 `FLAG_SECURE`。只验证密码时验证页直接画在幕布之上；需要系统锁屏凭据时由验证页承载（API 30+ 使用 BiometricPrompt 且只允许“设备凭据”，不采集生物特征；更低版本使用系统确认凭据页）。

**清除所有应用数据**（设置 → 通用 → 维护，或隐私保护页底部）调用系统自带的 `clearApplicationUserData()`，等同于 系统设置 → 应用信息 → 存储 → 清除存储空间，这是找回密码之外的另一条退路；保护开启时它需要先验证。

详细设计见 [`docs/PRIVACY_DESIGN.md`](docs/PRIVACY_DESIGN.md)。
